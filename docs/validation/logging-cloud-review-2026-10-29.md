# Logging and Cloud SQL review — 2026-10-29

This is an initial increment, not a complete implementation of the requested logging strategy or production performance investigation.

The container entrypoint configures an allowlist-based JSON formatter for the existing timing logger. It emits `severity`, `event`, `request_id`, `operation`, `duration_ms`, and `succeeded`. `operation.completed` and `operation.failed` represent timed stages. `retrieval.completed` additionally includes retrieval mode and returned semantic, lexical and final counts. These counts describe channel results after repository limits; they do not measure duplicates removed inside SQL. The retrieval completion duration starts after input/profile validation. HTTP context propagates the generated request ID to nested operations. The formatter never serializes the log message, exception, SQL, question, source text, vectors or credentials. Other existing application loggers have not yet been migrated to this JSON convention.

Example: `{"severity":"INFO","event":"retrieval.completed","request_id":"...","operation":"retrieval","duration_ms":123.4,"succeeded":true,"mode":"hybrid","semantic_count":20,"lexical_count":20,"result_count":5}`.

The managed Cloud SQL server was contacted through the existing local proxy with `default_transaction_read_only=on` and bounded statement timeouts. It reports PostgreSQL 18.6 and installed pgvector 0.8.5. `pg_textsearch` 1.3.1 is available but not installed. Read-only counts: 125,761 active nondeleted documents and 57,901 stored embeddings. The database indexes returned no vector ANN index or lexical BM25 index.

One read-only EXPLAIN ANALYZE used an existing stored embedding as a query vector, with a 15-second statement timeout. The exact vector query scanned 57,901 embedding rows; server execution was 269.3 ms, including a sequential scan taking 259.0 ms and top-five sorting. This is one warm observation of the embedding table only: it excludes source eligibility, complete-plan checks, application/network overhead, embedding generation, lexical ranking and RRF. It does not establish end-to-end latency or a p95. No rows or vector values were logged. The earlier local full-query measurements remain in `retrieval-correctness-2026-10-29.md`.
