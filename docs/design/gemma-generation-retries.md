# Gemma investigation generation retries

Gemma investigation turns use at most `GEMMA4_RETRY_MAX_ATTEMPTS` provider attempts (default 5, range 1–10). `GEMMA4_RETRY_TOTAL_TIMEOUT_SECONDS` can set a smaller positive whole-second deadline; when unset, the deadline is `GENERATION_TIMEOUT_SECONDS` (default 30 seconds). It must not exceed that timeout. The HTTP investigation deadline remains an independent outer limit. The SDK's own retries remain disabled (`attempts=1`). Gemini investigation and Quick Answer retry policies are unchanged.

Retries cover HTTP 500/502/503/504, timeouts, and selected transient network errors. A 429 is retried only when a valid structured retry hint or `Retry-After` is present and structured quota information does not identify exhausted quota. Without a hint it is not retried. HTTP 400/401/403/404, malformed responses and application validation failures are not retried. `Retry-After` and structured retry delays take precedence over a shorter random delay; if the wait cannot fit the deadline there is no retry. Full jitter draws from zero to `min(8, 2**(attempt-1))` seconds after a failed attempt. Backoff and evaluator pacing are asynchronous and subject to the same deadline and cancellation.

Only the failed logical model turn is retried. Its native conversation, call IDs, signatures, tool results and generation settings are reconstructed from the unchanged turn and retained provider state; retrieval is not repeated. A timeout or 5xx response does not prove that upstream processing did not occur, so a retry can incur duplicate provider work or charges. Only one accepted model decision is returned to the application.

`INVESTIGATION_MAX_GENERATION_REQUESTS` bounds both logical model turns and actual provider attempts for a single investigation. A successful response after retries counts as one logical turn, while each submitted attempt consumes the provider-attempt budget. The evaluator additionally reserves and paces every retry against its run-wide RPC cap. A retry can exhaust the provider-attempt budget before all logical turns are used; in that case the existing generation-limit result or the last provider failure is returned, depending on where the cap was reached.

`generation.provider_failed` is emitted once per failed provider request and includes attempt, maximum attempts, retry decision and planned delay; `generation.retry_recovered` and `generation.retry_exhausted` record the total attempts and elapsed time. `investigation.completed` or `investigation.failed` includes both logical generation requests and provider attempts. No prompt, evidence or credentials are included in these structured events.
