# Generation limits and usage

Google applies per-project, model-dependent limits including requests per minute (RPM), input tokens per minute (TPM), and requests per day (RPD). The actual limits depend on the model, project and usage tier; inspect the project's active limits in [Google AI Studio](https://aistudio.google.com/rate-limit). Google documents these dimensions and the daily reset in its [rate-limit guide](https://ai.google.dev/gemini-api/docs/rate-limits). This application does not assume a particular quota or a guaranteed reset time.

An investigation can make several generation requests. Each turn sends the conversation and accumulated tool responses, so later turns may consume more input tokens. Each provider retry is another request and may consume quota or incur provider work even if it fails. The per-investigation generation-attempt budget and overall deadline still apply. Gemma's bounded retry policy and its conservative treatment of quota exhaustion are described in [Gemma generation retries](gemma-generation-retries.md).

An upstream generation HTTP 429 is returned as HTTP 429 with a sanitized `error` object. Structured `QuotaFailure` fields can identify a per-minute token or request limit (`generation_rate_limit`), a daily limit (`generation_daily_quota`), or an unknown limit (`generation_quota_exceeded`). Unknown details are not assumed to mean a minute or a day. A valid provider `Retry-After` or `RetryInfo` delay is included as `retry_after_seconds` and in the `Retry-After` response header, adjusted for elapsed time. It is a provider hint, not a guarantee of recovery. The frontend avoids a one-minute suggestion for daily or unknown limits. Other provider failures retain their existing response mapping. Structured quota details can be absent or ambiguous, and no error text or quota identifiers are passed to users.

Model responses log provider-reported prompt, candidate, thinking, and, when supplied, total token counts with the request ID and turn number, including a response that later fails validation. The final investigation's usage and completion log aggregate successful turns only. A missing provider total stays unknown, rather than being inferred from the component counts. A failure or retry can consume upstream tokens without returning usage metadata; the totals therefore do not establish all quota consumption or billing. No additional token-counting call is made for generation telemetry.
